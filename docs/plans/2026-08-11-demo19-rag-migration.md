# RAG 工作流演进计划

## 当前基线

当前仓库已在 demo19 迁移基线上形成可独立运行和测试的真实索引闭环：

- 真实文档摄取、解析和切分。
- 真实 Embedding、PostgreSQL 持久化、完整性校验和原子发布。
- 真实结果构建。
- 可复用的公共工作流运行层。
- 本地命令、Eino Dev、单元测试、race 和 vet 验证。

源代码基线为 `eino-lab@31aba6b`。源 demo 暂时保持不变，方便迁移结果对照。

## 演进原则

1. 一次只启动一个里程碑。
2. 开始实现前先基于当前代码定位问题和约束。
3. 每个里程碑单独形成设计，明确接口、依赖、数据和失败语义。
4. 关键技术选择由用户参与确认后再落地。
5. 每个里程碑必须有可运行入口、测试和明确验收结果，不能只留下半成品节点。
6. 未启动的里程碑只描述目标，不提前展开任务或锁定技术方案。

## 后续候选里程碑

### 真实索引下游（已完成）

已用真实 Embedding、索引存储、校验和发布替换模拟节点，形成支持同 Set 重试复用的数据写入闭环。

V1 的入库边界、表结构、Embedding 写入、校验和原子发布方案记录在 [RAG 索引入库设计 V1](../designs/rag-index-storage-v1.md)。真实 PostgreSQL 与 Embedding API 的端到端验收已完成，并保留显式开启、租户隔离和自动清理的重复执行入口。

### RAG 查询工作流

目标：针对已发布索引完成检索、证据组织、答案生成和引用输出闭环。

开始前需要共同设计：查询输入输出、检索范围、召回与重排策略、上下文预算、无证据行为、模型选择和评测标准。

### 服务化运行入口

目标：根据实际调用方式提供稳定入口，并接入配置、观测、健康检查和优雅退出。

开始前需要共同设计：同步或异步调用方式、HTTP/RPC/任务入口、部署形态、鉴权边界和运行容量。

“真实索引下游”里程碑的配置、PostgreSQL/pgvector、`text-embedding-v4` 客户端、构建持久化、完整性校验、原子发布、工作流装配和真实外部依赖端到端验收均已完成。RAG 查询工作流和服务化入口尚未启动，需另行确认和设计后再进入。
