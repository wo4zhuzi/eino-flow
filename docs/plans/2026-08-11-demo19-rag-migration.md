# RAG 工作流演进计划

## 当前基线

当前里程碑只负责把 demo19 已完成能力迁入 `eino-flow`，并形成可独立运行和测试的闭环：

- 真实文档摄取、解析和切分。
- 模拟 Embedding、持久化、校验和发布。
- 真实结果构建。
- 可复用的公共工作流运行层。
- 本地命令、Eino Dev、单元测试、race 和 vet 验证。

源代码基线为 `eino-lab@31aba6b`。源 demo 暂时保持不变，方便迁移结果对照。

## 演进原则

1. 一次只启动一个里程碑。
2. 开始实现前先基于当前代码定位问题和约束。
3. 每个里程碑单独形成设计，明确接口、依赖、数据和失败语义。
4. 关键技术选择由用户参与确认后再落地。
5. 每个里程碑必须有可运行入口、测试和明确验收结果，不能只留下半成品节点。
6. 未启动的里程碑只描述目标，不提前展开任务或锁定技术方案。

## 后续候选里程碑

### 真实索引下游

目标：用真实 Embedding、索引存储、校验和发布替换当前模拟节点，形成可重复执行、可验证的数据写入闭环。

V1 的入库边界、表结构、Embedding 写入、校验和原子发布方案已经记录在 [RAG 索引入库设计 V1](../designs/rag-index-storage-v1.md)。实现前仍需确认实际 Embedding 模型与维度、数据库版本、失败恢复和验收语料。

### RAG 查询工作流

目标：针对已发布索引完成检索、证据组织、答案生成和引用输出闭环。

开始前需要共同设计：查询输入输出、检索范围、召回与重排策略、上下文预算、无证据行为、模型选择和评测标准。

### 服务化运行入口

目标：根据实际调用方式提供稳定入口，并接入配置、观测、健康检查和优雅退出。

开始前需要共同设计：同步或异步调用方式、HTTP/RPC/任务入口、部署形态、鉴权边界和运行容量。

## 当前状态

除“当前基线”外，其余里程碑均未启动、未定方案、未进入实现。
